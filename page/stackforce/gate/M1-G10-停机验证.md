Milestone: M1 Real Hardware Baseline

## 当前进度

已完成源码停机路径审计。发现 `setRobotparam()` 将 `flat = 1`，而 Device01 `loop()` 在 `flat==1` 时持续调用 `motors.setTargets(2,2)`；首次运动前必须冻结 G01 firmware baseline 并确认是否为刻意校准固件。

## 1. Gate 目标

回答 command、source、controller 或 communication 消失时，所有执行器是否进入可证明的安全状态。

## 2. Topics

PPM loss/invalid、CH7/CH8 mode、Device reset、CAN loss/stale command、Serial2/BLDC loss/stale target、IMU failure、servo enable GPIO42、watchdog/timeout、emergency power removal、boot/reboot 和 flat calibration mode。

## 4. Stop/Fault Contract

安全响应应为：检测输入/通信新鲜度失效，在有限时间内停止腿部命令、将 BLDC target 置零或进入硬件 disable，并记录 fault。当前代码不能证明这些响应对 CAN、PPM、Serial2 全部成立；特别是 Device02 的 last-command persistence 是未解决的 P0 SAFETY GAP。

## 5. Proposed Safety Patch（非 upstream）

独立 safety branch/test file 中增加：CAN/PPM/Serial2 last-receive timestamp、超时清零、mode transition failsafe、fault latch 和显式 servo disable。不得静默修改官方源码；在 G01 baseline 和硬件验证前，该 patch 标记 `NOT UPSTREAM / NOT RUNTIME VERIFIED`。
