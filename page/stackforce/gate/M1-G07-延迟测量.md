# M1-G07 延迟测量

Milestone: M1 Real Hardware Baseline
Gate: G07
Status: **INCOMPLETE — STATIC LATENCY CONTRACT COMPLETE / RUNTIME MEASUREMENT PENDING**

## 当前进度

软件路径和 timestamp 边界已定义；尚无真实 communication、actuator-response 或 mechanical latency 数据。三者不能合并为一个“机器人延迟”。

## 1. Gate 目标

测量从输入/command 到执行器命令、反馈和首次可观测运动的延迟分布及 jitter。

## 2. Topics

`T_input`、`T_compute`、`T_transport`、`T_actuator-command`、`T_feedback`、`T_mechanical`；PPM、CAN、Serial2、IMU/stabilization 和未来 host path。

## 3. Evidence

- PPM ISR 在 `SF_serveo_control/src/main.cpp:105-122` 用 `micros()` 捕获脉宽，但未记录 command recognition timestamp。
- Device01 在 `main.cpp:668-795` 顺序执行 input、IMU、mode、gait、stabilization 和 IK。
- Device01 CAN TX 在 `main.cpp:600-624` 受 1 ms 门控；Device02 在 `...device2/src/main.cpp:98-104` 非阻塞接收，在 `124-141` 以非固定周期写 BLDC。
- `SF_CAN::receiveMsg()` 只在收到匹配帧时更新 buffer，未提供新鲜度 timestamp。

## 4. Latency Contract

| Path | Start → end | 静态结论 | 真机证据 |
|---|---|---|---|
| A | PPM edge → control recognition | 调用顺序已知 | ISR/loop timestamp |
| B | control/IK → `setAngle()` | 函数路径已知 | MCU timestamp |
| C | Device01 CAN TX → Device02 RX | API 路径已知 | 双板同步 timestamp/CAN analyzer |
| D | Device02 RX → `setTargets()` | loop 结构已知 | runtime timestamp |
| E | wheel command → telemetry | API 存在 | packet/telemetry timestamp |
| F | IMU read → stabilization correction | 同一 loop 顺序 | runtime timestamp |
| G | host TX → actuator command | 当前无 host protocol，`DEFERRED` | 协议冻结后测量 |

机械延迟必须用高帧率视频、编码器或外部传感器定义 `command event → first observable motion`；MCU timestamp 差不能替代它。

## 5. Instrumentation Plan

共享、默认关闭的 `M1_G07_LATENCY_PROBE` 记录 `t_ppm`、`t_control`、`t_ik`、`t_servo_write`、`t_can_tx`、`t_can_rx`、`t_bldc_write`、`t_feedback`、`t_imu`、`t_stabilization`。使用 ring buffer/聚合输出，避免改变 normal behavior。

## INCOMPLETE — 当前 Gate Blockers

- Missing: 双板同步 runtime log；Required Evidence: 输入、CAN、BLDC、反馈 timestamp distribution；Exit: 报告 p50/p95/max、jitter、丢包和 stale data。
- Missing: mechanical observation；Required Evidence: 外部观测记录；Exit: 明确机械与软件/传输延迟的边界。

## 6. Runtime / Physical Validation Plan

架空轮体，先小幅 command；分别触发 PPM、CAN、Serial2 和 IMU 输入，记录 command、接收、写入、feedback 及视频事件，写明时钟同步误差。

## 7. Acceptance Criteria

- Static: 每条路径端点和证据边界已定义。
- Runtime: 每条已启用路径有分布而非单值，并报告 jitter、丢包和 stale data。
- Deferred: host path 等协议冻结后再测，不阻塞静态完成。
