# M1-03-控制接口与频率延迟

> 本页属于：stackforce 机器狗实战（M1 实操）
> 前置知识：[[M1-02-Joint-Map与单执行器]]
> 预计阅读时间：20 分钟

## 🎯 为什么需要这个？

搞清楚 actuator 到底接受什么 command，以及真实控制频率/延迟——这两件事直接决定 RL 的动作设计和仿真步长。

## M1.5 测真正的控制接口

StackForce actuator 接受的 command 可能是：

```text
Position      q_d
Velocity      dq_d
Torque        τ_d
MIT-style     τ = Kp(q_d - q) + Kd(dq_d - dq) + τ_ff
```

**源码已确认（CONFIRMED）：**

- **腿（8 舵机）**：PCA9685 PWM **position 命令**，开环、**无 feedback** → 当前硬件无法做 PD 闭环（缺位置/速度反馈）。第一版只能开环 position 命令，或后续换带编码器的 FOC 关节。
- **轮（4 BLDC）**：`motors.setModes(4,4)` = **TORQUE_MODE**（底层 `SF_Motor.h` mode 4），即轮是 **torque 命令**，不是速度命令（尽管变量名/注释写"目标速度"）。

因此第一版 Sim-to-Real 的 command 设计：

```text
腿  → 开环 PWM position 命令（无 feedback，PD 不可用）
轮  → torque 命令（mode 4，单位/标定待 U10 确认）
```

`q_des / dq_des / Kp / Kd / tau_ff`（MIT-style）在**当前腿硬件上暂不可用**（缺 encoder feedback）；只有给腿换成带编码器的 FOC 关节后才可行。

## M1.6 测控制频率和延迟

这一步很多人跳过，但后面 Sim-to-Real 非常关键。要测：

```text
Sensor rate :  f_IMU = ? Hz    f_encoder = ? Hz
Command rate:  f_control = ? Hz
延迟        :  t_command → t_motion 大约差多少
```

> 源码主 `loop()` 没有固定周期调度，不能仅凭代码声称某个 Hz；频率/jitter、CAN 发送频率都要实测（U11/U12）。

假设最后发现：

```text
Motor inner loop     1000 Hz
State reading         500 Hz
Host communication    200 Hz
RL policy             100 Hz
```

那么 Isaac Lab 应设计：

```text
Δt_policy = 0.01 s
```

而不是随便选 60 Hz。

## ✏️ 小练习

<details>
<summary>查看答案</summary>

按真实 RL 策略/通信频率定（如 100 Hz → 0.01 s），让仿真与实机控制节奏一致。
</details>

## M1-1 源码基线结论（Communication）

**CAN / TWAI**：TX GPIO35 / RX GPIO41，1 Mbit/s，extended 29-bit，accept all；Device 0x01 ID=0x01、Device 0x02 ID=0x02，payload 8 字节。

命令帧：target 限幅 `[-100,100]` → 各量化 unsigned 16-bit → byte0/1=target1、byte2/3=target2、byte4–7=0，发送 ID=0x02。target1=右前轮、target2=左前轮。

回传：Device 0x02 的速度回传代码**目前被注释** → 不能假设前轮速度经 CAN 返回。

**I2C**：`Wire.begin(1,2,400000)`（SDA GPIO1 / SCL GPIO2 / 400kHz），挂 PCA9685@0x40 + MPU6050。

**BLDC Serial2**：`SF_BLDC(Serial2)`；baud / TX/RX pins / packet 协议 / 周期仍 UNKNOWN。

**USB 调试串口**：115200；`read()` 可更新 pitch_off/roll_off。**尚无 PC 实时 state/action protocol** → Sim2Real 大概率需自建 host protocol。

## 本章小结

- 明确 command 类型（position/velocity/torque/MIT-style）。
- 第一版用 position+PD。
- 测 sensor/command 频率与延迟，据此定 Δt_policy。
