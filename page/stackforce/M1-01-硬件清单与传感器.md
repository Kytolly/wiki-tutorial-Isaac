## M1.1 建立硬件清单

把机器狗拆成信息流：

```text
                StackForce 四轮足
                      │
    ┌─────────────────┼─────────────────┐
    ▼                 ▼                 ▼
  Sensors         Controller        Actuators
    │                 │                 │
   IMU(MPU6050)    ESP32-S3 ×2     8×腿舵机(PCA9685)
  轮BLDC反馈(Vel)  CAN(TWAI)+I2C    4×轮电机(BLDC, torque)
```

第一份文档 `hardware_spec.md` 至少记录这些项。下面已按官方整机源码静态分析**预填**（`CONFIRMED`），仍未定的一律标 `UNKNOWN`，留待 M1-2 实机验证：

| 项目 | 源码已确认（CONFIRMED） | 待实机（UNKNOWN） |
|------|------------------------|-------------------|
| 主控型号 | ESP32-S3 DevKitC-1 ×2（Device 0x01 / 0x02） | 两块精确安装位置 |
| 软件框架 | Arduino / PlatformIO（espressif32@6.6.0） | — |
| IMU 型号 | MPU6050（I2C） | 角度/gyro 单位、更新率、安装旋转 |
| 腿部 actuator 数量 | 8（PCA9685 舵机，无反馈） | 物理 hip/knee 语义、零位、方向、限位 |
| 轮电机数量 | 4（BLDC，mode 4 = TORQUE_MODE） | 前轮内部 M0/M1 对应、真实正方向 |
| 编码器类型 | 腿舵机无反馈；轮 BLDC 有 `Vel` 等反馈 | 舵机内部是否有反馈 |
| 通信 | CAN(TWAI) + I2C + Serial2 + PPM + UART 115200 | Serial2 引脚/波特率/协议 |
| Motor ID | 后轮 M0/M1；前轮 CAN target1=右前、target2=左前 | 前轮 Device 0x02 内部 M0/M1 |
| 电池电压 | — | 待测 |
| 控制周期 | 主循环 `loop()` 无固定周期调度 | 待测（U11） |
| IMU 更新率 | — | 待测（U07） |

> **宁可写 UNKNOWN，也不要猜。** 上表 `待实机` 列就是当前必须保持 UNKNOWN 的部分，验证计划见 [[M1-05-硬件API与安全]]。

### 已确认的系统数据流与引脚

```text
PPM(GPIO40) → Device 0x01 → I2C(SDA1/SCL2,400k) → PCA9685@0x40(8舵机) + MPU6050
                           → Serial2 → 后轮双路 BLDC
                           → CAN 1Mbps extended → Device 0x02 → Serial2 → 前轮双路 BLDC
```

| 接口 | 参数 | 用途 | 状态 |
|------|------|------|------|
| I2C / Wire | SDA GPIO1, SCL GPIO2, 400 kHz | PCA9685、MPU6050 | CONFIRMED |
| CAN / TWAI | TX GPIO35, RX GPIO41 | Device 0x01 ↔ 0x02 | CONFIRMED |
| CAN bitrate | 1 Mbit/s | 控制器间通信 | CONFIRMED |
| CAN frame | Extended / 29-bit（`setMode(1)`） | 控制器间通信 | CONFIRMED |
| PPM | GPIO40 | 遥控器输入 | CONFIRMED |
| Debug Serial | 115200 baud | 调试输出/参数输入 | CONFIRMED |
| Serial2 | BLDC 库使用 | 双路无刷电机控制板 | CONFIRMED |
| Serial2 baud/pins | — | — | UNKNOWN |

控制职责（源码已确认）：Device 0x01 负责 PPM 解析 / IMU / 8 舵机 / 后轮双路 BLDC / 稳定 / 逆运动学 / 算前轮目标发 CAN；Device 0x02 收 CAN ID 0x02 的 8 字节命令并送给前轮双路 BLDC。

上位机实时控制接口：当前尚未确认（暂无正式 PC→机器人 state/action 协议），见 [[M1-03-控制接口与频率延迟]]。

## M1.2 跑通传感器（只读，不控制）

这是最安全的第一项实机实验。目标是得到：

```python
state = robot.read_state()
# state = {"imu": ..., "joint_pos": ..., "joint_vel": ..., "wheel_vel": ...}
```

### 源码已确认的传感器接口

- **IMU MPU6050**（I2C）：姿态 `pitch=getAngleX()+pitch_off(2)`、`roll=-getAngleY()+roll_off(-1)`、`yaw=getAngleZ()`；陀螺仪 API `getGyroX/Y/Z()`；加速度未用于整机控制；单位/更新率/安装旋转仍 UNKNOWN（U06/U07）。
- **BLDC 反馈** `SF_BLDC_DATA`：Angle/ElecAngle/Vel/Uq/Ud/Iq/Id，主程序只用了 M0_Vel / M1_Vel。底层 `SF_Motor` API（后续验证线索）：`getAnlge()` 角度单位 rad、`getVelocity()` 速度注释"单位 rad"（应实机核实为 rad/s）、`getCurrent()` 电流注释 mA。
- **舵机无反馈**：`SF_Servo` 只有 PWM 命令，无 position/velocity 反馈 API → Actor 观测不能默认依赖腿关节真实 encoder。
- **遥控 PPM**：GPIO40，8 通道，sync gap 3000μs；源码注释主要用途 CH1 左右转向、CH2 前进/后退、CH3 腿高、CH4 roll，其他通道用于速度/模式切换。

### 实机验证记录表（M1-2：源码给线索，最终以实机为准）

然后**手动操作机器人，验证每个信号的物理意义**。记录表（以后价值非常大）：

| 动作 | Sensor 变化 | 源码线索 |
|------|-------------|----------|
| 向前倾 10° | pitch = ? | 源码 `pitch=getAngleX()` |
| 向后倾 10° | pitch = ? | 同上，符号以实机为准 |
| 向左倾 | roll = ? | 源码 `roll=-getAngleY()` |
| 向右倾 | roll = ? | 同上，符号以实机为准 |
| FL 腿向前 | q_FL_hip ↑ / ↓ ? | 8 舵机 channel 见 [[M1-02-Joint-Map与单执行器]] |
| FL 膝关节弯曲 | q_FL_knee ↑ / ↓ ? | hip/knee 语义 U01 待实机 |
| FL 轮向前滚 | ω_FL ↑ / ↓ ? | 后轮 feedback sign 见 M1-02 |
| FR 轮向前滚 | ω_FR ↑ / ↓ ? | 前轮 feedback sign 待实机（U09） |

你真正要确定的是：

```text
正方向（boxed）
```

> 源码里 `roll` 用了 `-getAngleY()`，说明整机控制坐标 ≠ MPU6050 原始坐标，至少 roll 取了负号；且 `pitch_off=2`、`roll_off=-1`。这些是线索不是结论，M1-2 仍需实机姿态实验确认 base frame ↔ IMU frame 关系（U06）。

## ✏️ 小练习

**1.** 为什么第一步"只读不控制"？

<details>
<summary>查看答案</summary>

先确认传感器数值和物理意义、正方向，再动 actuator；否则控制实验里方向错了都不知道。
</details>

**2.** hardware_spec 里宁可写 UNKNOWN 的原因？

<details>
<summary>查看答案</summary>

猜错的参数会在 URDF/RL/Sim2Real 阶段集中爆发；未知就显式标 UNKNOWN，之后用实验填上。
</details>

## 本章小结

- 建立 hardware_spec.md：主控/IMU/actuator/编码器/通信/电池/Motor ID/频率，源码已确认的预填、未确认的标 UNKNOWN。
