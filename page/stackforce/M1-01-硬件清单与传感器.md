# M1-01-硬件清单与传感器

## 🎯 为什么需要这个？

M1 的第一件事不是控制，而是**把机器狗拆成信息流，建立 hardware_spec.md**，然后只读传感器验证每个信号。宁可写 UNKNOWN，也不要猜。

## M1.1 建立硬件清单

把机器狗拆成信息流：

```text
                StackForce 四轮足
                      │
    ┌─────────────────┼─────────────────┐
    ▼                 ▼                 ▼
  Sensors         Controller        Actuators
    │                 │                 │
   IMU             MCU/主控          8×腿关节？
  Encoders        CAN/RS485?         4×轮电机？
  Voltage
  Current
```

第一份文档 `hardware_spec.md` 至少记录：

| 项目 | 需要确认 |
|------|----------|
| 主控型号 | ? |
| IMU 型号 | ? |
| 腿部 actuator 数量 | ? |
| 轮电机数量 | 4 |
| 编码器类型 | ? |
| 通信 | CAN / RS485 / UART ? |
| 电池电压 | ? |
| Motor ID | ? |
| 控制周期 | ? |
| IMU 更新率 | ? |

> **宁可写 UNKNOWN，也不要猜。**

## M1.2 跑通传感器（只读，不控制）

这是最安全的第一项实机实验。目标是得到：

```python
state = robot.read_state()
# state = {"imu": ..., "joint_pos": ..., "joint_vel": ..., "wheel_vel": ...}
```

然后**手动操作机器人，验证每个信号的物理意义**。记录表（以后价值非常大）：

| 动作 | Sensor 变化 |
|------|-------------|
| 向前倾 10° | pitch = ? |
| 向后倾 10° | pitch = ? |
| 向左倾 | roll = ? |
| 向右倾 | roll = ? |
| FL 腿向前 | q_FL_hip ↑ / ↓ ? |
| FL 膝关节弯曲 | q_FL_knee ↑ / ↓ ? |
| FL 轮向前滚 | ω_FL ↑ / ↓ ? |
| FR 轮向前滚 | ω_FR ↑ / ↓ ? |

你真正要确定的是：

```text
正方向（boxed）
```

## ✏️ 小练习

**1.** 为什么第一步"只读不控制"？

<details>
<summary>查看答案</summary>

先确认传感器数值和物理意义、正方向，再动 actuator；否则控制实验里方向错了都不知道。
</details>

**2.** hardware_spec 里宁可写 UNKNOWN 的原因？

<details>
<summary>查看答案</summary>

猜错的参数会在 URDF/RL/Sim2Real 阶段集中爆发；未知就显式标 UNKNOWN，之后用实验填上。
</details>

## 本章小结

- 建立 hardware_spec.md：主控/IMU/actuator/编码器/通信/电池/Motor ID/频率。
- 只读传感器：read_state()，手动操作验证每个信号物理意义与正方向。
