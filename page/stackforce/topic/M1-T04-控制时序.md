# M1-T04 控制时序

## Scope

描述 action 到达执行器、observation 返回控制器的链路，并用实测数据冻结频率、延迟和抖动。

## 指令语义

- 8 个腿舵机：PCA9685 PWM position command，开环，无源码反馈；当前不能实现依赖腿部 encoder 的闭环 PD。
- 4 个轮 BLDC：`setModes(4, 4)` 对应 `TORQUE_MODE`。CAN 中的 `[-100, 100]` 是协议编码范围，不是 rad/s、N·m 或 A。
- MIT-style `q_des / dq_des / Kp / Kd / tau_ff` 不能直接假定适用于当前腿部硬件。

## CAN 命令帧

Device `0x01` 将两个目标限制到 `[-100, 100]`，量化为 unsigned 16-bit 后发送到 ID `0x02`：

```text
byte 0/1: target1（右前轮）
byte 2/3: target2（左前轮）
byte 4/5/6/7: 0
```

CAN 参数为 TX GPIO35、RX GPIO41、1 Mbit/s、extended 29-bit、payload 8 字节。Device `0x02` 的速度回传代码被注释。

## I2C 与 BLDC

```cpp
Wire.begin(1, 2, 400000UL);
SF_BLDC motors = SF_BLDC(Serial2);
```

I2C 挂载 PCA9685 `0x40` 和 MPU6050。Serial2 的底层 packet/timeout 行为仍受预编译库限制。Device01 CAN TX 有 1 ms 软件门限；Device02 CAN RX 非阻塞，BLDC write 由无固定周期的 loop 计数触发。bus bitrate、软件更新率和控制频率不是同一指标。

## 测量协议

记录以下时间序列：

```text
f_IMU, f_encoder, f_control, f_CAN
t_command_to_motion, jitter, timeout_behavior
```

主循环 `loop()` 没有固定周期调度，不能由源码直接声明控制 Hz。IMU update-call timing 已实测为 175.3 Hz；代表性 servo/local-wheel/remote-wheel 在 500 ms command window 内出现可观测响应，automatic STOP 为 501.535–502.498 ms。精确 onset、transport-only latency 与逐通道分布仍是 evidence debt。

current source 使用 `flat=0`，PPM 和 CAN 均具 100 ms freshness zeroing；旧 snapshot 风险不再是当前行为。现有 blocker 是 ch7 在 firmware return/STOP 后仍物理上抬。
